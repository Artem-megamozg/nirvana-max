Nirvana MAX — навигатор по мерам поддержки

Бот и мини-приложение в мессенджере MAX, которые помогают человеку понять, какие меры государственной поддержки ему положены, что нужно подготовить и какой следующий шаг предпринять.

Проект для хакатона MAX (Changellenge), трек «Забота о людях».

Проблема

Информация о льготах распределена между ведомствами, условия зависят от региона и жизненной ситуации, а порядок действий неочевиден. Человек не понимает, что именно ему положено, теряет время на поиск и повторные обращения.

Решение

Анкета из 3-5 вопросов — минимальные данные для подбора.

Персональная выдача — список мер с объяснением «почему подходит».

Чек-лист документов — что подготовить по каждой мере.

Маршрут — задачи с дедлайнами и напоминаниями.

Напоминания в MAX — чтобы не пропустить срок.

Кнопка «Открыть Nirvana» в боте — переход в мини-апп.

Архитектура

MAX (мессенджер) → FastAPI backend (main.py) → storage.py (SQLite) + rules.py (движок правил) + data/catalog.json.

Эндпоинты FastAPI:

/webhook — вебхук от бота MAX
/api/profile — профиль (все поля)
/api/profile/:id/meta — meta-поля (ФИО, телефон)
/api/recommendations — подбор мер
/api/measures/:id — карточка меры и чек-лист
/api/tasks — маршрут задач
/api/reminders — напоминания (CRUD)
/api/explain — «Почему подходит»
/app — мини-приложение (React)

Технологии

Backend: Python 3.11, FastAPI, uvicorn, httpx, SQLite
Frontend: React, Vite, @maxhub/max-ui
Платформа: MAX Bot API (platform-api2.max.ru)

Быстрый старт (Docker)

git clone <repo-url> nirvana-max
cd nirvana-max
cp .env.example .env
заполнить MAX_TOKEN, WEBHOOK_SECRET
docker compose up --build -d
curl http://localhost:8000/health

Остановить: docker compose down

Быстрый старт (локально, без Docker)

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
заполнить MAX_TOKEN, WEBHOOK_SECRET
uvicorn main:app --host 0.0.0.0 --port 8000

Сборка фронтенда:

cd frontend
npm install
npm run build

Vite собирает в ../web, ничего копировать не надо.

Переменные окружения

MAX_TOKEN — токен бота из MAX for Developers
MAX_BOT_USERNAME — username бота (для кнопки open_app)
MAX_WEBAPP_URL — публичный HTTPS-URL мини-приложения
WEBHOOK_SECRET — секрет для проверки вебхука MAX
INCOME_PM_THRESHOLD — порог дохода для флага income_below_pm

Порты

8000 — FastAPI (вебхук, API, статика мини-аппа по /app/)

Проверка работоспособности

curl http://localhost:8000/health
curl http://localhost:8000/api/scenarios
curl -X POST http://localhost:8000/api/recommendations -H "Content-Type: application/json" -d '{"user_id":"test","children_count":2,"income_below_pm":true}'

Известные ограничения (честно)

Каталог мер модельный. 34 меры по 3 сценариям, все помечены data_status: "model". Суммы, условия и ссылки требуют сверки с официальными источниками (СФР, Госуслуги, Минздрав).

Нет реальных интеграций с ЕГИССО, Госуслугами, ЕГИСЗ — всё хранится в локальной SQLite.

Региональные меры не детализированы. Указан только регион уровня субъекта, без муниципальных различий.

Нуждаемость упрощена до одного порога INCOME_PM_THRESHOLD.

Вебхук требует HTTPS для production — Nginx и Let's Encrypt.

Тестовая БД — data/nirvana.db создаётся при первом запуске. Для чистого старта: rm data/nirvana.db.

Порядок проверки основного сценария

В MAX открыть бота, отправить /start, нажать «Открыть Nirvana».

В мини-аппе открыть вкладку «Профиль» и заполнить ФИО, телефон, регион, возраст, занятость, доход, детей. Сохранить.

На главной нажать «Мед. маршрут» или другой сценарий. Если профиль полный — сразу экран подтверждения. Нажать «Всё верно, строить маршрут».

В результатах открыть меру, посмотреть «Почему подходит», нажать «Добавить в маршрут».

В маршруте доступны кнопки «Завершить», «Напомнить», «Открыть».

В напоминаниях видны созданные записи с описанием, можно удалить крестиком.

Nirvana сокращает путь пользователя от «не понимаю, что мне положено»
до «знаю, что делать и в каком порядке».

Гипотеза эффекта (проверяется на пилоте):

Время поиска: ~40 минут самостоятельного изучения источников → 3 минуты в Nirvana.

Ручные действия: 2–3 обращения в МФЦ / ведомства → 1 обращение по готовому чек-листу.

Повторные обращения: снижение за счёт готового списка документов и объяснения «почему подходит».

Доля завершённых сценариев: пользователь доходит до маршрута и создаёт задачу — целевой показатель 60%+.

Точность подбора: пользователь не пропускает меры, на которые имеет право, — целевой показатель 80%+.

Как измерять на пилоте:

Метрики воронки: сколько дошли до результатов, сколько добавили задачу, сколько завершили.

Среднее число подобранных мер на пользователя.

Доля мер, по которым открыли чек-лист документов.

NPS / оценка полезности после прохождения сценария.

Все цифры выше — гипотеза, требующая подтверждения на реальной аудитории.

Масштабирование

Nirvana проектировалась как переносимый продукт: логика отделена
от данных, данные — от инфраструктуры.

Ядро продукта (не меняется при масштабировании):

Логика сценариев и движок правил (rules.py).

Архитектура (FastAPI + SQLite + React-мини-апп).

Пользовательский путь: профиль → подбор → маршрут → напоминания.

Интерфейсные компоненты мини-аппа.

Модель данных профиля и задач.

Переменная часть (адаптируется под регион):

Содержимое catalog.json — перечень региональных и федеральных мер.

Ссылки на региональные ведомства и формы подачи.

Названия региональных льгот и их условия.

Список доступных регионов в справочнике.

План тиражирования:

Пилот в одном регионе — например, Ставропольский край.

Собрать 30–40 реальных мер с официальных источников.

Провести с ограниченной группой (студенты, молодые семьи).

Расширение на 2–3 соседних региона.

Добавить региональные меры через catalog.json.

Проверить работу ссылок на подачу.

Федеральный уровень.

Интеграция с ЕГИССО / Госуслугами (при наличии API).

Подключение региональных информационных систем.

Что потребуется для каждого шага:

Данные: официальные источники, справочники, ссылки на формы.

Интеграции: на первом этапе не требуются, на втором — региональные API,
на третьем — ЕГИССО / ЕПГУ.

Ресурсы: команда контента (сверка мер), разработка (интеграции),
партнёрство с региональными органами соцзащиты.

Юридическое: подтверждение актуальности формулировок, дисклеймеры,
соответствие 152-ФЗ.

Риски масштабирования:

Региональные меры быстро устаревают — нужна регулярная сверка.

Не у всех мер есть публичные ссылки на подачу — часть останется
в формате «чек-лист + адресат».

Языковая и цифровая доступность — для отдельных аудиторий
потребуется адаптация интерфейса.
