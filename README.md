# Nirvana MAX — навигатор по мерам поддержки

Бот и мини-приложение в мессенджере MAX, которые помогают человеку
понять, какие меры государственной поддержки ему положены, что нужно
подготовить и какой следующий шаг предпринять.

Проект для хакатона MAX (Changellenge), трек «Забота о людях».

---

## Проблема

Информация о льготах распределена между ведомствами, условия зависят
от региона и жизненной ситуации, а порядок действий неочевиден. Человек
не понимает, что именно ему положено, теряет время на поиск и повторные
обращения.

## Решение

- Анкета из 3–5 вопросов — минимальные данные для подбора.
- Персональная выдача — список мер с объяснением «почему подходит».
- Чек-лист документов — под каждое ведомство свой.
- Блок «Куда и что делать» — адресат, срок, пошаговая инструкция.
- Маршрут — задачи с напоминаниями в MAX.
- Обратная связь 👍/👎 — сигнал команде контента.
- Кнопка «Открыть Nirvana» в боте — переход в мини-апп.

## Архитектура

MAX (мессенджер)
   ↓
FastAPI backend (main.py)
   ├── /webhook                    вебхук от бота MAX
   ├── /api/profile                профиль (все поля)
   ├── /api/profile/:id/meta       meta-поля (ФИО, телефон)
   ├── /api/recommendations        подбор мер
   ├── /api/measures/:id           карточка меры + чек-лист
   ├── /api/measures/:id/feedback  👍/👎 обратная связь
   ├── /api/tasks                  маршрут задач
   ├── /api/reminders              напоминания (CRUD)
   ├── /api/explain                «Почему подходит» + GigaChat
   └── /app                        мини-приложение (React)
   ↓
storage.py (SQLite)                profiles, tasks, checklist,
                                   reminders, history, benefit_feedback
rules.py (движок правил)           проверка условий и подбор
gigachat_client.py                 клиент GigaChat через CA Минцифры
data/catalog.json                  68 мер, 5 сценариев, чек-листы,
                                   шаги и источники
frontend/                          исходники React + Vite
web/                               собранная статика (Vite кладёт сюда)

## Технологии

- Backend: Python 3.11, FastAPI, uvicorn, httpx, SQLite
- Frontend: React, Vite, @maxhub/max-ui
- LLM: GigaChat-2-Pro (Сбер), опционально
- Платформа: MAX Bot API (platform-api2.max.ru)

## Быстрый старт (Docker)

    git clone <repo-url> nirvana-max
    cd nirvana-max
    cp .env.example .env
    # заполнить MAX_TOKEN, WEBHOOK_SECRET
    # опционально: GIGACHAT_AUTH_KEY
    docker compose up --build -d

    curl http://localhost:8000/health

Остановить:

    docker compose down

## Быстрый старт (локально, без Docker)

    python3 -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt
    cp .env.example .env
    # заполнить MAX_TOKEN, WEBHOOK_SECRET
    uvicorn main:app --host 0.0.0.0 --port 8000

### Сборка фронтенда

    cd frontend
    npm install
    npm run build
    # Vite собирает в ../web, ничего копировать не надо

## Как проверить основной сценарий

1. Откройте бота в MAX: https://max.ru/t687_hakaton_max_bot
2. Отправьте /start — бот пришлёт приветствие и кнопку
   «Открыть Nirvana».
3. Нажмите кнопку — откроется мини-приложение.
4. Заполните профиль (или откройте демо-профиль через
   ?demo=demo_family в веб-версии).
5. Выберите сценарий → заполните данные → «Построить маршрут».
6. Откройте меру → посмотрите «Почему подходит» →
   нажмите «Добавить в маршрут».
7. Перейдите в раздел «Маршрут» — задача появилась.
8. Нажмите «Напомнить» — в течение минуты бот пришлёт
   напоминание в MAX.
9. В карточке меры проверьте блоки «Куда и что делать»,
   «Источник и актуальность» и 👍/👎.
10. На экране результатов — блок «Что вы сэкономили».

## Ожидаемое поведение

- Бот отвечает на /start, /help, /scenario, /status.
- Команда /scenario присылает 4 inline-кнопки.
- Мини-приложение открывается из любой кнопки open_app.
- Подбор мер работает по всем 5 сценариям.
- Напоминания доставляются в MAX в течение минуты.
- Обратная связь 👍/👎 сохраняется в БД.
- Все действия сохраняются в SQLite (data/nirvana.db).
- GigaChat переписывает «Почему подходит» человеческим
  языком, если задан GIGACHAT_AUTH_KEY.
  Иначе возвращается шаблон (source: rules_engine).

## Ожидаемый эффект

Nirvana сокращает путь пользователя от «не понимаю, что мне положено»
до «знаю, что делать и в каком порядке».

Гипотеза эффекта (проверяется на пилоте):

- Время поиска: ~40 минут самостоятельного изучения источников
  → 3 минуты в Nirvana.
- Ручные действия: 2–3 обращения в МФЦ → 1 обращение
  по готовому чек-листу.
- Повторные обращения: снижение за счёт готового списка документов
  и объяснения «почему подходит».
- Доля завершённых сценариев: целевой показатель 60%+.
- Точность подбора: 80%+ (пользователь не пропускает меры,
  на которые имеет право).

Как измерять на пилоте:

- Метрики воронки: сколько дошли до результатов, сколько
  добавили задачу, сколько завершили.
- Среднее число подобранных мер на пользователя.
- Доля мер, по которым открыли чек-лист документов.
- NPS / оценка полезности после прохождения сценария.

Все цифры выше — гипотеза, требующая подтверждения на реальной
аудитории.

## Масштабирование

Ядро продукта (не меняется при масштабировании):

- Логика сценариев и движок правил (rules.py).
- Архитектура (FastAPI + SQLite + React-мини-апп).
- Пользовательский путь: профиль → подбор → маршрут → напоминания.
- Интерфейсные компоненты мини-аппа.
- Модель данных профиля, задач и обратной связи.

Переменная часть (адаптируется под регион):

- Содержимое catalog.json — перечень региональных
  и федеральных мер.
- Ссылки на региональные ведомства и формы подачи.
- Названия региональных льгот и их условия.
- Список доступных регионов в справочнике.

План тиражирования:

1. Пилот в одном регионе — например, Ставропольский край.
   - Собрать 30–40 реальных мер с официальных источников.
   - Провести с ограниченной группой (студенты, молодые семьи).
2. Расширение на 2–3 соседних региона.
   - Добавить региональные меры через catalog.json.
   - Проверить работу ссылок на подачу.
3. Федеральный уровень.
   - Интеграция с ЕГИССО / Госуслугами (при наличии API).
   - Подключение региональных информационных систем.

Что потребуется для каждого шага:

- Данные: официальные источники, справочники, ссылки на формы.
- Интеграции: на первом этапе не требуются, на втором —
  региональные API, на третьем — ЕГИССО / ЕПГУ.
- Ресурсы: команда контента (сверка мер), разработка
  (интеграции), партнёрство с региональными органами соцзащиты.
- Юридическое: подтверждение актуальности формулировок,
  дисклеймеры, соответствие 152-ФЗ.

Риски масштабирования:

- Региональные меры быстро устаревают — нужна регулярная сверка.
- Не у всех мер есть публичные ссылки на подачу — часть
  останется в формате «чек-лист + адресат».
- Языковая и цифровая доступность — для отдельных аудиторий
  потребуется адаптация интерфейса.

## API и документация

Решение предоставляет собственный REST API (FastAPI).

Адрес проверяемого API:

- https://litvinskiy-developer.online

Спецификации:

- openapi.json — автоматически сгенерированная схема FastAPI
  (OpenAPI 3.1).
- DATA-API.yaml — описание обязательных проверок для платформы
  оценки: методы, параметры, статус-коды, формат ответа.

Собственный API не обязателен по ТЗ, но позволяет проверить
работу продукта независимо от MAX и удобен для отладки.

## Внешние сервисы

- MAX Bot API (https://platform-api2.max.ru) — обязателен
  для работы бота. Требует токен MAX_TOKEN и сертификат
  Минцифры (уже включён в образ через certs/).
- GigaChat API (https://gigachat.devices.sberbank.ru) —
  опционально. Используется для переписывания блока
  «Почему подходит» человеческим языком.
  Ключ: GIGACHAT_AUTH_KEY. Модель: GigaChat-2-Pro.
  Если ключ не задан — работает шаблон.
  Запросы идут через сертификат Минцифры (уже в образе),
  TLS-проверка остаётся включённой.
- Nginx + Let's Encrypt (или другой HTTPS-прокси) —
  обязателен для production-вебхука.

Все внешние сервисы, кроме MAX Bot API, опциональны.
Основной сценарий работает и без них (в режиме локального
запуска через мини-апп в браузере).

## Известные ограничения (честно)

- Каталог мер модельный. 68 мер по 5 сценариям, все помечены
  data_status: "model". Суммы, условия и ссылки требуют
  сверки с официальными источниками (СФР, Госуслуги,
  Минздрав, МВД).
- Нет реальных интеграций с ЕГИССО, Госуслугами, ЕГИСЗ —
  всё хранится в локальной SQLite.
- Региональные меры не детализированы. Указан только регион
  уровня субъекта, без муниципальных различий.
- Нуждаемость упрощена до одного порога INCOME_PM_THRESHOLD.
- Вебхук требует HTTPS для production — Nginx + Let's Encrypt.
- Тестовая БД — data/nirvana.db создаётся при первом запуске.
  Для чистого старта: rm data/nirvana.db.
- GigaChat работает опционально. Если ключ не задан —
  блок «Почему подходит» показывает шаблон.
- GigaChat не добавляет факты, только переписывает уже
  готовые причины. Если API недоступен — возвращается
  шаблон (source: rules_engine).
- Черновик заявления (интерфейс) в разработке —
  полная генерация запланирована после MVP.
