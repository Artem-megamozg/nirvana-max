# Nirvana

Маршрут помощи внутри MAX. Бот и мини-приложение, которые за пару минут
отвечают на вопрос «что мне положено, что принести и куда идти», а потом
не дают забыть про следующий шаг.

Хакатон MAX (Changellenge), трек «Забота о людях».

Бот: https://max.ru/t687_hakaton_max_bot
API: https://litvinskiy-developer.online

---

## Зачем это нужно

Меры поддержки разбросаны по ведомствам. Условия зависят от региона,
возраста, состава семьи и десятка мелочей, а порядок действий обычно
выясняется на третьем визите в МФЦ. Люди не отказываются от льгот, они о
них просто не узнают или сдаются на этапе сбора справок.

Nirvana работает как проводник. Она не пытается заменить Госуслуги, она
берёт на себя самую неприятную часть пути: разобраться, собрать, не
пропустить.

## Как выглядит путь пользователя

1. В чате с ботом нажимаешь «Открыть Nirvana», ничего ставить не нужно.
2. Выбираешь жизненную ситуацию: семья и дети, переезд, медицинский
   маршрут, студенты, пенсионеры.
3. Отвечаешь на три-пять вопросов, остальное подтянется из профиля.
4. Получаешь список мер, и у каждой написано, почему она подходит именно
   тебе.
5. В карточке меры лежит всё нужное: чек-лист документов, куда подать,
   пошаговая инструкция, срок рассмотрения, ссылка на официальный
   источник.
6. Добавляешь меру в маршрут, ставишь напоминание, и бот сам напишет в MAX
   в нужный момент.

## Что внутри

| Блок | Что делает |
|---|---|
| Подбор мер | Движок правил сверяет профиль с каталогом и считает, насколько мера подходит |
| Объяснение | Для каждой меры показаны условия, которые выполнены, и чего не хватает |
| Чек-листы | Документы отдельно под каждое ведомство, галочки сохраняются |
| Маршрут | Задачи по выбранным мерам с прогрессом и историей действий |
| Напоминания | Бот присылает сообщение в MAX точно в назначенное время |
| Помощник | Чат на GigaChat в правом нижнем углу, отвечает только про сервис |
| Обратная связь | Оценка меры прямо в карточке, сигнал команде контента |
| Приватность | Явное согласие на обработку данных, удаление профиля одной кнопкой |

### Чат-помощник

Круглая кнопка «Помощь» есть на каждом экране. Внутри диалог с GigaChat,
которому передан каталог мер и правила поведения: отвечать только про
Nirvana и меры поддержки, не выдумывать суммы и сроки, не давать
медицинских и юридических заключений. На любой посторонний вопрос модель
возвращает фиксированный отказ. Без ключа GigaChat окно открывается и
честно сообщает, что помощник не настроен.

### Каталог

68 мер по пяти сценариям: семья и дети (25), медицина (17), переезд (13),
студенты (7), пенсионеры (6). У каждой меры есть условия подбора,
документы, шаги, ведомство, срок и источник. Каталог лежит в
`data/catalog.json`, добавить меру значит дописать запись, код менять не
нужно.

## Архитектура

```
MAX (мессенджер)
   │  вебхук, inline-кнопки, open_app
   ▼
FastAPI (main.py)
   ├── /webhook                    события бота: /start, /help, /scenario, /status
   ├── /api/profile, /consent      профиль и согласие на данные
   ├── /api/recommendations        подбор мер
   ├── /api/measures, /checklist   карточка меры и чек-лист
   ├── /api/tasks, /reminders      маршрут и напоминания
   ├── /api/explain                «Почему подходит», GigaChat по желанию
   ├── /api/chat                   чат-помощник
   └── /app                        мини-приложение, собранный React
   │
   ├── rules.py               движок правил
   ├── storage.py             SQLite, миграции при старте
   ├── gigachat_client.py     GigaChat через сертификат Минцифры
   └── data/catalog.json      мероприятия, сценарии, шаги, источники
```

Воркер напоминаний живёт внутри приложения и каждые 30 секунд проверяет,
что пора отправить.

## Запуск

### Docker

```bash
cp .env.example .env
# заполни MAX_TOKEN и WEBHOOK_SECRET, при желании GIGACHAT_AUTH_KEY
docker compose up --build -d
curl http://localhost:8000/health
```

### Локально

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn main:app --host 0.0.0.0 --port 8000
```

Мини-приложение откроется на `http://localhost:8000/app/`.

### Фронтенд

```bash
cd frontend
npm install
npm run build
```

Vite собирает сразу в `web/`, копировать ничего не нужно. Для разработки
подойдёт `npm run dev`.

### Демо-данные

```bash
python seed.py
```

Появятся три профиля: `demo_family` (Анна Петрова, двое детей,
Ставропольский край), `demo_large` (Сергей Иванов, трое детей, Москва) и
`demo_relocation` (Мария Сидорова, переезд, Краснодарский край).
Открыть любой из них в браузере можно параметром:

```
http://localhost:8000/app/?demo=demo_family
```

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `MAX_TOKEN` | токен бота из MAX for Developers |
| `MAX_BOT_USERNAME` | username бота для кнопки open_app |
| `MAX_WEBAPP_URL` | публичный HTTPS-адрес мини-приложения |
| `WEBHOOK_SECRET` | секрет проверки вебхука |
| `INCOME_PM_THRESHOLD` | порог дохода на члена семьи для флага нуждаемости |
| `GIGACHAT_AUTH_KEY` | ключ GigaChat, без него работают шаблоны, а чат отвечает, что он не настроен |

## Как проверить за пять минут

1. Открой бота в MAX и отправь `/start`, придёт приветствие и кнопка
   «Открыть Nirvana».
2. Пройди согласие, выбери сценарий, заполни данные и нажми «Построить
   маршрут».
3. Открой любую меру, посмотри блоки «Почему подходит», «Куда и что
   делать», чек-лист и источник.
4. Добавь меру в маршрут и поставь напоминание, в течение минуты бот
   напишет в MAX.
5. Нажми «Помощь» справа внизу и задай вопрос про сервис, потом
   что-нибудь постороннее и посмотри, как помощник держит рамки.

Без MAX то же самое работает в браузере по ссылке с `?demo=demo_family`.

Бот понимает команды `/start`, `/help`, `/scenario` (четыре кнопки выбора
ситуации) и `/status`.

## API

У решения есть открытый REST API, по нему можно проверить продукт без
MAX.

* `openapi.json` схема, сгенерированная из работающего приложения
* `DATA-API.yaml` описание проверок для платформы оценки
* Интерактивная документация FastAPI доступна на `/docs`

## Внешние сервисы

* MAX Bot API (`platform-api2.max.ru`) обязателен, нужен токен. Сертификат
  Минцифры уже лежит в `certs/` и попадает в образ.
* GigaChat API необязателен. Ключ в `GIGACHAT_AUTH_KEY`, модель
  GigaChat-2-Pro, проверка TLS остаётся включённой.
* HTTPS-прокси (Nginx и Let's Encrypt) нужен для боевого вебхука.

Всё, кроме MAX Bot API, можно не подключать, основной сценарий работает и
без остального.

## Что мы ожидаем от пилота

Это гипотезы, а не измерения, и проверять их нужно на живой аудитории.

* Поиск нужной меры сокращается с примерно сорока минут до трёх.
* Вместо двух или трёх визитов в МФЦ хватает одного, с готовым чек-листом.
* Не меньше 60 процентов начатых сценариев доходят до результата.

Мерить будем воронку (дошёл до результата, добавил задачу, завершил),
долю открытых чек-листов, среднее число подобранных мер и оценку
полезности после сценария.

## Как это масштабируется

Ядро остаётся тем же: движок правил, модель данных, путь «профиль, подбор,
маршрут, напоминания». Меняется только контент: каталог мер, ссылки на
региональные ведомства и справочник регионов.

1. Пилот в одном регионе, например в Ставропольском крае, 30 или 40 проверенных
   мер и ограниченная группа: студенты и молодые семьи.
2. Два или три соседних региона, региональные меры добавляются через каталог.
3. Федеральный уровень с интеграцией с ЕГИССО и Госуслугами, когда
   появится доступ к API.

Для этого нужны команда контента для сверки мер, партнёрство с органами
соцзащиты и юридическая вычитка формулировок в рамках 152-ФЗ.

## Честно об ограничениях

* Каталог модельный. Все 68 мер помечены `data_status: "model"`, суммы,
  условия и ссылки нужно сверить с СФР, Госуслугами, Минздравом и МВД
  перед боевым запуском.
* Интеграций с ЕГИССО, Госуслугами и ЕГИСЗ нет, всё хранится в локальной
  SQLite.
* Региональные меры описаны на уровне субъекта, без муниципальных
  различий.
* Нуждаемость упрощена до одного порога `INCOME_PM_THRESHOLD`.
* Правила подбора сейчас работают по схеме «все условия сразу», без
  веток «или».
* GigaChat только переписывает готовые причины и не добавляет фактов.
  Ограничение чата по теме держится на системном промпте, так что на
  боевом ключе его стоит проверить отдельно.
* Боевой вебхук MAX требует HTTPS.
* Черновик заявления пока не реализован.
